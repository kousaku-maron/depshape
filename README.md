# depshape

git の差分で **フォルダ・ファイル間の依存関係がどう変わったか** を、既存の構造と並べてブラウザで可視化するツールです。
push 前のローカルレビューで、コード差分を見る前に「追加した部分の依存の形が、既存の部分と揃っているか」を確かめるために使います。

ツールはファイルの役割（handler / usecase など）を理解しません。依存関係という事実だけを、比べやすい形で見せます。判断はレビューする人が行います。

Go と TypeScript / JavaScript に対応しています。Go や Node のツールチェーン、`npm install` は不要で、git から直接ソースを読みます（比較元の `main` なども、チェックアウトせずにそのまま解析します）。

## 使い方

解析したいリポジトリの中で実行します（Node.js 20 以上と git が必要です）。

```bash
npx @kousaku-maron/depshape . main --merge-base
```

よく使うなら `npm install -g @kousaku-maron/depshape` で入れておくと、`depshape` コマンドとして使えます。以下の表の `depshape` は、npx で使う場合は `npx @kousaku-maron/depshape` と読み替えてください。

| コマンド | 比較内容 |
|---|---|
| `depshape` | 未コミットの変更すべて vs HEAD |
| `depshape . main --merge-base` | 現在の作業ディレクトリ vs main からの分岐点（GitHub の PR と同じ見え方） |
| `depshape @ main --merge-base` | HEAD（コミット済み）vs main からの分岐点 |
| `depshape . abc1234` | 現在の作業ディレクトリ vs 特定のコミット |
| `depshape abc1234` | そのコミット単体の変更 |
| `depshape staged` / `depshape working` | ステージ済み / 未ステージの変更のみ |

オプション: `--port <n>`（デフォルト 4977、使用中なら +1）、`--host`、`--no-open`、`--json`（解析結果を標準出力へ）

サーバーはデフォルトで `127.0.0.1` だけで待ち受け、`localhost` / `127.0.0.1` 宛て以外のリクエストは拒否します。`--host 0.0.0.0` などを指定すると、同じネットワークの他の端末からリポジトリのファイル構成と依存関係が見えるので注意してください（ソースコードの中身は送りません）。

画面右上の「再読み込み」で、AI がファイルを書き換えた後の状態を再解析できます。

## 画面の見方

画面はヘッダー（比較の対象と変更の件数）と、左のツリー・右の依存のパネルだけのシンプルな構成です。

- **ツリー**: 同じフォルダの中身を1列に名前順（フォルダ → ファイル）で並べます。矢印は描かず、今回 import が増えた行に「+n 依存」の印を付けます。表示範囲は2つあります。
  - **変更まわり**（既定）: GitHub の PR のように、変更したファイル・その依存先・間のフォルダだけを表示します。各フォルダの変更のないファイル・フォルダは「ほか N ファイル」の1行にまとまり、クリックするとその場で開いて中身が並び、もう一度クリックで閉じます（変更のあったものは常にその上に表示）。この行はパネルには表示できないので、既存のファイルと比べたいときはフォルダを表示して、パネルで開いてください。フォルダは見出しのクリックで閉じたり開いたりでき（閉じたフォルダの行には中の「+n 依存」がまとめて出ます）、「すべて開く」で元に戻せます。1本道のフォルダは `apps/api/internal/` のように1行にまとめます。
  - **全体**: リポジトリ全体のツリー。フォルダをクリックで開閉します。
- **依存のパネル**: ツリーの行にホバーしている間、その行がパネルに出ます。行のピンのアイコンでピン留めすると表示し続けるので、複数並べると「a と b は hoge を共有、c だけ fuga」のような依存の形を比べられます。ホバー中の行は点線の枠で一時的に加わります。パネルは3列です（依存元がなければ2列）。
  - **真ん中 = ピン留め**: ピン留めしたファイル / フォルダ（とホバー中の行）を、左のツリーと同じパス順に並べます。フォルダは ▸ でその場で開き、下のフォルダと直下のファイルごとに分けられます（どのファイルから出ている線かを確かめたいとき）。開いたフォルダの中同士の import は描きません
  - ピン留めしたファイルは親フォルダの点線の箱にまとまります。箱を ▾ でたたむと、ピン留めしたファイルの依存が依存先ごとに1本の線になります（箱に入るのはピン留めしたファイルだけで、フォルダ全体ではありません）。Go では依存元の線は常に箱（パッケージ）に届きます
  - **右 = 依存先（使っているもの）**: ピン留めしたものが import している先を、フォルダの入れ子のツリーで並べます（dependency-cruiser のフォルダの枠と同じ考え方）。フォルダの行を ▾ でたたむと、配下への依存が1本の線にまとまります。TypeScript では、フォルダを ▸ で開くと実際に import しているファイルが並び、フォルダ直下で import しているファイルはそのフォルダの中に直接並びます。Go はパッケージが単位なので、ファイルには開けません（親のフォルダ自体も import されているときは「（パッケージ）」の行が出ます）
  - **左 = 依存元（使っている側）**: ピン留めしたものを import しているファイルを、同じくフォルダのツリーで並べます。フォルダは「N ファイル」とまとめて出し、▸ で開くとファイルが並びます。TypeScript はそのファイルを直接 import しているもの、Go はそのパッケージを import しているものです
  - 今回増えた依存は緑、なくなった依存は赤の点線、`import type` だけの依存は細かい点線。フォルダからの線には import しているファイル数（「13→17」= 変更前→変更後）が付き、太さにも反映されます
  - 左右の列のピンのアイコンを押すと、そのフォルダ / ファイルが真ん中にもピン留めされ、さらに先の依存・依存元をたどれます
  - パネルの行を右クリックして「非表示」を選ぶと、その行は半透明になり、出入りする線を描かなくなります（テストからの大量の依存など、一旦どけたい線に）。フォルダの行なら、開いたときの中の行も同じです。半透明の行を右クリックして「表示」で戻せます（「すべて表示」で全部戻ります）。非表示は保存せず、再読み込みで元に戻ります
  - 各列の行に共通する親フォルダは列の上に「〜 以下」と1回だけ出し、各行はそこからの相対パスで表示します。入りきらない長いパスは、名前を残して真ん中のフォルダから「…」に省きます（完全なパスはホバーで表示）
- **コメント**（difit のようなレビューコメント）:
  - ヘッダーの「💬 件数（未対応 n）」で右端のコメントサイドバーを開閉し、「AI 用にすべてコピー」で未対応のコメントを Claude Code / Codex などに貼れるプロンプトとしてコピーします
  - パネルの矢印をクリックすると選択（⌘ / Shift + クリックで追加・解除）。箱をクリックすると、そこから出る依存（真ん中・左の列）/ そこに入る依存（右の列）をまとめて選べます。ツリーの行は 💬 で単独、⌘ / Shift + クリックで選択に追加できます。選択するとサイドバーが開きます
  - サイドバーの下の入力欄に、選んだもの（コメント先）がチップで入ります。⌘Enter で保存、Esc でキャンセル。依存を選んだあと `c` キーで入力欄に移れます
  - 一覧はコメントが付いたファイル / フォルダごとにまとまり、「未対応のみ / すべて」で絞り込めます。各コメントの「コピー」でその1件だけをコピー、対象をクリックで図に表示、編集・削除もできます。カードにホバーすると図の該当する依存が、矢印にホバーすると該当するカードが光ります
  - コピーされるプロンプトには、各依存のフルの import パス、今回追加か既存か、同じフォルダの既存ファイルの主な依存先（参考）が自動で添えられます
  - 再読み込み後、コメントした依存やファイルがなくなった場合は「解消済み？」（一部なら「一部解消」）と表示し、すべてコピーの対象から外します
  - コメントはリポジトリと比較の対象ごとにブラウザに保存されます
- ツリー・パネル・コメントサイドバーの間の仕切り線はドラッグで幅を変えられます（ダブルクリックで元の幅に戻ります）。幅とコメントサイドバーの開閉はブラウザに保存され、どのリポジトリでも前回の状態で開きます（サイドバーは最初は閉じていて、依存や行を選ぶと開きます）。
- ツリーで開いているフォルダとピン留めした項目は、リポジトリごとにブラウザに保存されます（パネルの中の開閉は保存しません）。

## 解析の仕様

### Go
- 対象: `.go` ファイルの import と `go.mod` の module 宣言（モノレポの複数 go.mod に対応。最長一致で解決）
- 標準ライブラリの import は無視。外部パッケージは「外部パッケージも表示」で表示
- `vendor/`、`testdata/`、`.` や `_` で始まるディレクトリは対象外

### TypeScript / JavaScript
- 対象: `.ts` `.tsx` `.mts` `.cts` `.js` `.jsx` `.mjs` `.cjs` の `import` / `export ... from` / `import()` / `require()`
- import 先の解決:
  - 相対パス（`./` `../`）は拡張子と `index` を補って解決（`./util.js` → `util.ts` のような ESM の書き方にも対応）
  - そのファイルから一番近い `tsconfig.json` / `jsconfig.json` の `paths`（`@/*` など）と `baseUrl`。リポジトリ内の `extends` もたどります（npm パッケージの設定を `extends` している部分は読めないので無視）
  - ワークスペースのパッケージ（名前のある `package.json`）は、リポジトリ内のそのパッケージに解決
  - それ以外は外部パッケージ（`react`、`@tanstack/react-query` など）。Node の標準モジュール（`node:fs` など）は無視
  - CSS・画像などのアセットや、存在しないファイルへの import は対象外
- import 先はファイル単位で分かるので、パネルではフォルダにまとめて表示しつつ、開くとファイル単位で見られます（矢印にホバーしても、実際に import しているファイルが出ます）。`import type` だけで使っているかどうかもファイルごとに判定します
- `node_modules/` と `.` で始まるディレクトリ（`.next` など）は対象外。Go と違い `_` で始まるディレクトリ（Next.js の `_components` など）は対象です
- 変数を使った動的な import（`import(path)`）や、Vue / Svelte のファイルは解析しません

## 開発

```bash
pnpm install
pnpm test        # パーサ・差分計算・ビューのテスト
pnpm typecheck
pnpm build       # dist/ に CLI と UI をビルド
node dist/cli.js --no-open   # 解析したいリポジトリの中で
```

## 今後の予定

- 変更の影響範囲（変更したファイルを間接的に使っているところ）の表示
- 依存の線から、その import 行やコードの差分を見る
- API 仕様（OpenAPI）の差分との連携
