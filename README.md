# depshape

git の差分で **フォルダ・ファイル間の依存関係がどう変わったか** を、既存の構造と並べてブラウザで可視化するツールです。
push 前のローカルレビューで、コード差分を見る前に「追加した部分の依存の形が、既存の部分と揃っているか」を確かめるために使います。

ツールはファイルの役割（handler / usecase など）を理解しません。依存関係という事実だけを、比べやすい形で見せます。判断はレビューする人が行います。

現在は Go に対応しています（Go のツールチェーンは不要。git から直接ソースを読みます）。

## 使い方

解析したいリポジトリの中で実行します（Node.js 20 以上と git が必要です）。

```bash
npx depshape . main --merge-base
```

よく使うなら `npm install -g depshape` で `depshape` コマンドとして入れておけます。以下の表の `depshape` は、npx で使う場合は `npx depshape` と読み替えてください。

| コマンド | 比較内容 |
|---|---|
| `depshape` | 未コミットの変更すべて vs HEAD |
| `depshape . main --merge-base` | 現在の作業ディレクトリ vs main からの分岐点（GitHub の PR と同じ見え方） |
| `depshape @ main --merge-base` | HEAD（コミット済み）vs main からの分岐点 |
| `depshape . abc1234` | 現在の作業ディレクトリ vs 特定のコミット |
| `depshape abc1234` | そのコミット単体の変更 |
| `depshape staged` / `depshape working` | ステージ済み / 未ステージの変更のみ |

オプション: `--port <n>`（デフォルト 4977、使用中なら +1）、`--host`、`--no-open`、`--json`（解析結果を標準出力へ）

サーバーはデフォルトで `127.0.0.1` だけで待ち受け、`localhost` / `127.0.0.1` 宛て以外のリクエストは拒否します。`--host 0.0.0.0` などを指定すると、同じネットワークの他の端末からリポジトリのファイル構成と依存関係が見えるので注意してください（ソースコードの中身は送りません）。

画面右上の「再読み込み」で、AI がファイルを書き換えた後の状態を再解析できます。

## 画面の見方

画面はヘッダー（比較の対象と変更の件数）と、左のツリー・右の依存のパネルだけのシンプルな構成です。

- **ツリー**: 同じフォルダの中身を1列に名前順（フォルダ → ファイル）で並べます。矢印は描かず、今回 import が増えた行に「+n 依存」、同じ名前の `_test.go` がない変更ファイルに「テストなし」の印を付けます。表示範囲は2つあります。
  - **変更まわり**（既定）: GitHub の PR のように、変更したファイル・その依存先・間のフォルダだけを表示します。各フォルダの変更のないファイル・フォルダは「ほか N ファイル」の1行にまとまり、クリックするとその場で開いて中身が並び、もう一度クリックで閉じます（変更のあったものは常にその上に表示）。フォルダは見出しのクリックで閉じたり開いたりでき（閉じたフォルダの行には中の「+n 依存」がまとめて出ます）、「すべて開く」で元に戻せます。1本道のフォルダは `apps/api/internal/` のように1行にまとめます。
  - **全体**: リポジトリ全体のツリー。フォルダをクリックで開閉します。
- **依存のパネル**: ツリーの行にホバーすると、その行の依存先が右に図で出ます。行の目のアイコンをオンにすると表示し続けるので、複数並べると「a と b は hoge を共有、c だけ fuga」のような依存の形を比べられます。ホバー中の行は点線で一時的に加わります。
  - 左の列 = 表示中・ホバー中のファイル / フォルダ / 「ほか N ファイル」、右の列 = それらが import しているパッケージ（共通の親フォルダは上に1回だけ表示）
  - 今回増えた依存は緑、なくなった依存は赤の点線。フォルダや「ほか N ファイル」からの線には import しているファイル数が付き、太さにも反映されます
  - 右の列のパッケージをクリックするとそれも左の列に表示され、さらに先の依存をたどれます
- **コメント**（difit のようなレビューコメント）:
  - ヘッダーの「💬 件数（未対応 n）」で右端のコメントサイドバーを開閉し、「AI 用にすべてコピー」で未対応のコメントを Claude Code / Codex などに貼れるプロンプトとしてコピーします
  - パネルの矢印をクリックすると選択（⌘ / Shift + クリックで追加・解除）。左右の箱をクリックすると、そこから出る / そこに入る依存をまとめて選べます。ツリーの行は 💬 で単独、⌘ / Shift + クリックで選択に追加できます。選択するとサイドバーが開きます
  - サイドバーの下の入力欄に、選んだもの（コメント先）がチップで入ります。⌘Enter で保存、Esc でキャンセル。依存を選んだあと `c` キーで入力欄に移れます
  - 一覧はコメントが付いたファイル / フォルダごとにまとまり、「未対応のみ / すべて」で絞り込めます。各コメントの「コピー」でその1件だけをコピー、対象をクリックで図に表示、編集・削除もできます。カードにホバーすると図の該当する依存が、矢印にホバーすると該当するカードが光ります
  - コピーされるプロンプトには、各依存のフルの import パス、今回追加か既存か、同じフォルダの既存ファイルの主な依存先（参考）、テストの有無が自動で添えられます
  - 再読み込み後、コメントした依存がなくなった・ファイルが消えた・足りなかったテストが追加された場合は「解消済み？」（一部なら「一部解消」）と表示し、すべてコピーの対象から外します
  - コメントはリポジトリと比較の対象ごとにブラウザに保存されます
- 開いているフォルダと表示中の項目は、リポジトリごとにブラウザに保存されます。

## 解析の仕様

- 対象: `.go` ファイルの import と `go.mod` の module 宣言（モノレポの複数 go.mod に対応。最長一致で解決）
- 標準ライブラリの import は無視。外部パッケージは「外部パッケージも表示」で表示
- `vendor/`、`testdata/`、`.` や `_` で始まるディレクトリは対象外
- Go のテストは同じパッケージに置かれることが多く import の矢印にならないため、テストの有無は同名の `_test.go` の存在で表示しています

## 開発

```bash
pnpm install
pnpm test        # パーサ・差分計算・ビューのテスト
pnpm typecheck
pnpm build       # dist/ に CLI と UI をビルド
node dist/cli.js --no-open   # 解析したいリポジトリの中で
```
