# dbshape

git の差分で **PostgreSQL のスキーマがどう変わったか** を見せる、[diffshape](../diffshape) のモジュールです（左のアイコンバーの「DB」）。
push 前のローカルレビューで、次の3つをすばやく確かめるために使います。

- 新しいテーブルは何か
- 既存のテーブルで何が変わったか（カラム・制約・外部キー・インデックス。削除も含む）
- enum のように使っているカラムで、値が増えた・減ったものはあるか

リポジトリの中の SQL ファイルだけを git から読みます。DB への接続、Docker、外部サービスは使いません。依存関係という事実だけを見せ、危険かどうかの判断はレビューする人が行います。

> マイグレーションとの対応付け（rename の判定など）はこれからです。

## 使い方

解析したいリポジトリの中で実行します（Node.js 20 以上と git が必要です）。

```bash
npx @kousaku-maron/diffshape . main --merge-base
```

diffshape は依存と DB の両方を開きます。DB だけを開くなら、同じパッケージに入っている `dbshape` コマンドを使います。比較の指定は [depshape](../depshape) と同じです。

| コマンド | 比較内容 |
|---|---|
| `dbshape` | 未コミットの変更すべて vs HEAD |
| `dbshape . main --merge-base` | 現在の作業ディレクトリ vs main からの分岐点（GitHub の PR と同じ見え方） |
| `dbshape abc1234` | そのコミット単体の変更 |
| `dbshape staged` / `dbshape working` | ステージ済み / 未ステージの変更のみ |

オプション: `--schema <glob>`（スキーマの SQL ファイル。複数指定可。`diffshape` でも使えます）、`--port <n>`（デフォルト 4977、使用中なら +1）、`--host`、`--no-open`、`--clean`（この比較のレビューコメントと確認済みのマークを消してから開く）。`dbshape` だけのもの: `--text`（サーバーを起動せず、要約をターミナルへ）、`--json`（差分を JSON で標準出力へ）、`--no-color`

サーバーはデフォルトで `127.0.0.1` だけで待ち受け、`localhost` / `127.0.0.1` 宛て以外のリクエストは拒否します。`--host 0.0.0.0` などを指定すると、同じネットワークの他の端末からスキーマが見えるので注意してください。

## 画面の見方

数の表し方は依存モジュールと共通で、**色はテーブル（や型）の状態**（緑 = 新規、黄 = 変更、赤 = 削除）、**`+` / `−` / `~` はテーブルの中身**（カラム・制約・インデックス）の追加・削除・変更だけに使います。

- **上の行**: `テーブル A 1 M 2 D 1 | 値の変化 2` のように、新規・変更・削除したテーブルの数（ホバーで内訳）と値の変化の件数、確認済みの数。比較の対象と「再読み込み」（AI がスキーマを書き換えた後などに）は diffshape の共通ヘッダーにあります。
- **真ん中 = ER 図の差分**: テーブルを箱、外部キーを線で描き、PostgreSQL のスキーマごとに点線の枠でまとめます。
  - テーブルの状態は箱の色で、新規は緑、削除は赤（点線・取り消し線）、変更は黄色。カラムの行には `+` / `−` / `~` が付きます。型の変更は `integer → bigint` のように出ます
  - 「変更まわり」（既定）は、変更したテーブルと、その外部キーの参照先のテーブル（薄く表示）だけを出します。「全体」ですべてのテーブルを出します
  - 箱に出るカラムは、変更したカラム・主キー（◆）・外部キー（FK）・値が変わったカラム（値±）・ほかのテーブルから参照されているカラムです。残りは「他 N カラム」にまとまり、クリックで開きます
  - 外部キーの線は、そのカラムの行から参照先のカラムの行へ引きます。テーブルにホバーすると、そのテーブルの線が強調されます
  - CHECK の式やインデックスの変更は ER 図では表せないので、箱の下に「制約 1・インデックス 1 の変更」と件数だけ出します
  - ドラッグ（またはスクロール）で移動、⌘ / Ctrl + スクロール（トラックパッドのピンチ）で拡大縮小、「全体を表示」で画面に収めます
- **右 = 詳細パネル**: テーブルをクリックすると開きます（Esc で閉じる）。カラム・制約・インデックス・コメントの変更を変更前（赤の取り消し線）→ 変更後（緑）で、CHECK の値の増減を `+追加` / `−削除` のチップで表示します。外部キーの参照先が今回の変更に含まれていれば `↗` で移動できます。見出しには中身の増減（`+2 −1 ~3`）が出ます。「確認済み」を付けると図と一覧で薄く表示します（リポジトリと比較の対象ごとにブラウザに保存され、そのテーブルがまた変わると外れます）
- **左の一覧**: 新規・変更・削除したテーブル、値の変化、型（ENUM 型・DOMAIN）、コメント。テーブルの行は状態を色で、中身の増減を右の `+2 −1 ~3` で示します。クリックすると図のそのテーブルへ移動して詳細を開きます。行にホバーすると出るチェックで、その場で「確認済み」にもできます。テーブル名・カラム名で絞り込めます
- 一覧・図・パネルの間の線をドラッグすると幅を変えられます（ダブルクリックで元に戻ります。幅はブラウザに保存されます）

## レビューコメント

詳細パネルの各行（テーブル・カラム・制約・インデックス・値の変化・型）にホバーすると出る 💬 から、コメントを書けます（⌘ / Ctrl + Enter で保存）。コメントのあるテーブルは図の右上に `💬 2`、カラムの行に青い点が付きます。

共通ヘッダーの「AI 用にコピー」で、未対応のコメントを「DB スキーマ」の見出しの下にコピーします（ほかのモジュールのコメントもまとめてコピーします）。各コメントは difit と同じく、1行目が指す先（SQL ファイルの定義位置と対象の名前。`db/sql/billing.sql:L42 カラム billing.invoices.price_id`、削除されたものは `(old)` つき）、続けてコメント本文で、コメント同士は `=====` で区切ります。

修正後に「再読み込み」すると、コメントの状態が分かります。

- **解消済み？**: 対象がなくなったか、コメントしたときの変更が取り消されて比較元と同じに戻った。コピーには含めません
- **コメント後に変更あり**: コメントしたあとに、対象の変更の内容が変わった

コメントは「確認済み」と同じく、リポジトリと比較の対象ごとにブラウザ（localStorage）に保存されます。外部には送りません。

## どのファイルを読むか

- 既定では、リポジトリの中の `atlas.hcl` の `src` に書かれた `file://` のパスを読みます（Atlas の宣言型の管理）。Atlas は実行せず、設定ファイルを文字列として読むだけです。フォルダが指定されていれば、その直下の `.sql` を名前順に読みます。
- Atlas を使っていなければ、`--schema 'db/schema/**/*.sql'` のように指定します。
- **DB が複数ある場合**（monorepo で `services/*/db/atlas.hcl` が並んでいる、など）は、DB ごとに別々に比べます。
  - 1つの `atlas.hcl` を1つの DB として扱います。同じファイルの中でも、`env` ごとに読む SQL ファイルが重ならなければ別の DB です（dev / prod のように同じファイルを読む `env` は1つにまとめます）。
  - 画面では、件数の行の先頭で DB を切り替えます（最初は変更のいちばん多い DB）。DB が1つなら切り替えは出ません。
  - `--schema` では `--schema billing=services/billing/**/*.sql --schema catalog=services/catalog/**/*.sql` のように名前を付けると、それぞれ別の DB になります。
  - コメントは DB ごとに保存されます。AI 用のコピーでは1つの一覧にまとまり、定義のファイルで DB を見分けます。
- 比較元と変更後のそれぞれで探すので、PR で追加・削除されたスキーマファイルも比較に入ります。

## 何を比べるか

SQL は PostgreSQL 本体と同じ構文解析器（[libpg-query](https://github.com/constructive-io/libpg-query-node) の WebAssembly 版）で読み、文を順に適用してスキーマを組み立てます。`CREATE TABLE` の中に制約を書く形も、pg_dump のように `ALTER TABLE ONLY ... ADD CONSTRAINT` で後から足す形も、同じスキーマになります。比較は構文木で行うので、改行や空白、`integer` と `int4` のような書き方の違いは変更になりません。

| 対象 | 内容 |
|---|---|
| テーブル | 追加・削除。追加・削除されたテーブルは、カラム・制約・インデックスをすべて表示 |
| カラム | 追加・削除・型・NOT NULL・デフォルト・IDENTITY・生成列・コメントの変更 |
| 制約 | 主キー・ユニーク・外部キー（参照先と ON DELETE / ON UPDATE）・CHECK の追加・削除・変更。名前のない制約は PostgreSQL と同じ規則で名前を付けて比べます（`invoices_pkey`、`invoices_price_id_fkey` など） |
| インデックス | 追加・削除・対象カラムや式、UNIQUE、WHERE などの変更 |
| 値の変化 | 既存のカラムで、値として許されるものの増減。読み取るのは SQL に書かれたものだけです |
| 型 | ENUM 型・DOMAIN の追加・削除・変更 |

### 値の変化として読むもの

- CHECK の値リスト: `col IN ('a', 'b')`、`col = ANY (ARRAY['a', 'b'])`（pg_dump の書き方。`::text` などのキャストがあっても可）、`col = 'a' OR col = 'b'`（`col IS NULL OR ...` も可）
- ENUM 型の値（その型を使っているカラムも表示）
- DOMAIN の CHECK の値リスト

アプリのコードの定数（Go や TypeScript の型など）は読みません。値の増減を見落としたくない文字列のカラムには、CHECK を付けておくとここに出ます。値を読み取れない CHECK（範囲や正規表現など）は、制約の変更として式の変更前 → 変更後を表示します。

### 比較しないもの

関数・ビュー・トリガー・権限（GRANT）・拡張などの文は読み飛ばし、件数だけを表示します。構文エラーで読めなかったファイルがあると、そのファイルのテーブルは比較から外して注意を表示します（ファイル全体が削除されたように見えないようにするためです）。

## 開発

[diffshape](https://github.com/kousaku-maron/diffshape) リポジトリの `packages/dbshape` にあります。`src/` が解析（`dbAnalyzer`）、`ui/` が画面（`dbModule`）です。リポジトリのルートで `pnpm install` したあと、このフォルダで実行します。

```bash
pnpm test        # スキーマの組み立て・CHECK の値・差分・ER 図のデータと配置・コメントのテスト
pnpm typecheck
```

動かして見るときは、`packages/diffshape` をビルドして `dist/bin/dbshape.js` を実行します。
